## 结论

1. **五个模型都能在 Mac 上跑**（llama.cpp 或 MLX），没有因不适配被剔除。
2. **逐行喂法否决**：重复行、单行循环，所有模型都比整页差很多（OvisOCR2 逐行 CER 98%）。
3. **整页喂法必须加闸门**：除 PaddleOCR-VL 外都会在白页编造上千字。
   产品里 VLM 调用前先查墨迹（无墨迹不调用），调用后查输出长度 / 重复循环，并与 CTC 引擎逐行对齐核对。
4. **现有融合有缺陷**：同一行被两个检测框各读一遍、其中一条开头带乱码时没被去重（第 12 页），
   融合 CER 反而比单引擎差。Phase 3 移植时修。
5. **PDF 文字层**：是第三方 OCR，不能当真值。抽查中正文分歧多数判文字层对，但这只说明那份 OCR 质量不错；书前页（馆藏章、目录）明显是乱码。
6. **线上**：qwen3.5-ocr 便宜、快、准，适合作可选在线引擎 / 裁决；Qwen3-VL-32B 白页也会编造。
