# Phase 4 结果：PP-OCRv6 Core ML

## 与 RapidOCR 对拍（20 页，590 行，两边都关逐行方向分类）

| 配置 | 逐行完全一致率 | 框 IoU | 最大偏差 |
|---|---|---|---|
| float16，`.cpuAndNeuralEngine` | 98.14% | 0.9967 | 6.3px |
| float16，`.all` | 98.14% | 0.9967 | 6.3px |
| float16，`.cpuAndGPU` | 98.31% | 0.9973 | 4.3px |
| float16，`.cpuOnly` | 97.63% | 0.9960 | 35.9px |
| float32，`.cpuOnly` | 98.31% | 0.9980 | 4.2px |

`MLComputePlan`：det 190、rec 211、cls 181 个算子全部规划在 ANE。默认 `.cpuAndNeuralEngine`。

## 速度

| 配置 | 秒/页（只算 PP-OCR） |
|---|---|
| RapidOCR（onnxruntime） | 1.165 |
| ANE，批大小 16 | 0.16 |
| ANE，含整页方向判定 | 0.21 |
| CPU，批大小 16 | 0.30 |

批处理在 ANE 上只提速约 12%。之前测到的 0.60 秒/页是 CTC 解码把输出逐元素拷出来造成的，不是 ANE 慢。

## 任意页面尺寸

判定口径（用户决定，2026-11-01）：**字符一致率 ≥ 99.5%；不足 20 行的类别样本太小，只记录不判定。**
字符一致率 = 1 − 整页文字串的编辑距离 / 参照字数。参照是 RapidOCR；超长页例外，RapidOCR 自己读成乱码，
参照改成拼图用的源页各自的读法。

| 类型 | 图数 | 行数 | 逐行完全一致率 | 字符一致率 | 判定 |
|---|---|---|---|---|---|
| 超大图 | 2 | 55 | 98.18% | 0.9991 | 过 |
| 标准开本 | 5 | 136 | 97.79% | 0.9992 | 过 |
| 随机缩放 | 8 | 240 | 96.25% | 0.9987 | 过 |
| 跨页横版 | 5 | 279 | 96.06% | 0.9984 | 过 |
| 超长页 | 3 | 373 | 93.03% | 0.9975 | 过 |
| 小图 | 4 | 23 | 86.96% | 0.9918 | **不过** |
| 窄带 | 3 | 4 | 50.00% | 0.9716 | 样本不足，不判定 |
| 合计 | 30 | 1110 | 95.05% | 0.9980 | |

小图不过：368 字里差 3 个编辑（空格、破折号），样本只比 20 行门槛多 3 行，不足以说明系统性问题，但按口径记为不过。

做法：常见尺寸走固定形状模型上 ANE；其他尺寸走可变尺寸检测模型（CPU/GPU），输入始终精确，不补白；
高瘦页（高宽比 > 3）按短边分块；超宽页（宽高比 > 8）按 RapidOCR 的做法纵向补边。

## 整页方向

8 页人为旋转 0/90/180/270，全部恢复，行恢复率都是 0.9806（与正放相同）。竖排判定没有用真实竖排页验证。

## 方向分类器

逐行方向分类默认关闭：它把正常长行判成 180°，整行倒过来读成乱码，这是 RapidOCR 乱码的根因。

## 模型分发

`ocr-cli models fetch` 从 GitHub Release `models-v1` 下载，校验 sha256 后放到
`~/Library/Application Support/DocOCR/models/`。全新目录实测：匿名下载 12 秒，`doctor` 全过，`book` 10 页 0.88 秒/页。

## 小图补样

P4 的小图类 4 张 23 行差 3 个编辑，按口径不过。又截了 20 张（种子 2，截法相同，`bench/p4_small.py`），结果写 `bench/results/p4-small.json`。

| 项 | 数 |
|---|---|
| 图 / 行 / 字符 | 20 / 95 / 1571 |
| 字符一致率 | **0.9917，不过** |
| 丢行 / 多行 | 0 / 0 |
| 编辑 | 13（字母数字 8，标点 3，空格 2） |
| 逐字相同的图 | 12 / 20 |
| 编辑落在被裁切线切开的行端（贴图边一头的 2 字内） | 9 |
| 只算行内编辑的字符一致率 | 0.9975 |

两次都是 0.992 左右，不是样本偶然，而是这种截法的系统性结果：截图竖切穿文字，95 行里 91 行有一头是残字，两边读法不稳。
检测没有问题，也没有丢行。行内编辑只有 4 处，换算 0.9975，高于门槛。判定仍记为不过，门槛不因此调整；这一类不反映完整小图的表现。
